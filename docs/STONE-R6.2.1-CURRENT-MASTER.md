## 1. Governance Layer 与 Runtime Layer 严格分离

### Governance Layer｜治理层

只负责：
- 本次使用哪个版本；
- 执行层级；
- 哪些 Gate 必须先通过；
- 证据等级；
- 冲突与平手如何处理；
- 什么时候必须停止继续推演；
- 结论如何被版本化、验证与回测。

治理层不得创造命理结论，也不得为了让报告“更完整”替 Runtime 补答案。

### Runtime Layer｜判读层

只负责按照 R6.1 继承的固定主判顺序，从当前确定性盘面与允许使用的证据中产生结构判断、时间判断与现实策略。

Runtime 不得绕过治理层的 Gate；Governance 也不得反向改写 Runtime 的计算输入或已锁定证据。

## 2. Progressive Execution｜渐进执行

所有分析按 L1 → L2 → L3 渐进展开。用户要求“深度”不等于可以跳过前置 Gate。

### L1｜速批／最小可靠链

至少完成：
- 资料校验；
- 特殊格局候选 Gate；
- 月令／调候／根气透藏与有路；
- 主格局方向、偏枯六态 Gate、主要病药、承载与流通；
- 与问题直接相关的大运／流年（如问题涉及时间）；
- GF-13 最小反证；
- 直接回答、限制与一个最优先行动。

未执行模块必须标为未执行，不得用模板句冒充已检查。

### L2｜标准分析

在 L1 通过后增加：
- 格局完成度／容量；
- 官杀专判与十神战局；
- 刑冲合害破与墓库；
- 与本题有关的六亲；
- 大运交接、LBX、事件辨识；
- 系统化反证与可信度分级。

### L3｜深度研究

在 L2 通过后执行完整 CURRENT 主链，并按触发条件调用紫微、七政、一掌经、D60、神煞、纳音等独立旁证；旁证仍不得与子平平权投票。

## 3. Stage Checkpoint｜阶段检查点

每次从 L1 升到 L2、从 L2 升到 L3 前，必须记录四件事：

1. 上一层已经确认的结构；
2. 尚未解决的 UNKNOWN／冲突；
3. 本次升级要解决的具体问题；
4. 若升级后仍无法解决，允许的最高结论强度。

如果上一层关键 Gate 未通过，不得通过堆叠更多旁证来“救活”主结论。

## 4. No Silent Reinterpretation｜禁止静默改口

同一份确定性 engine snapshot／同一组输入上的已记录结论，后续只能出现以下三种状态：

- `UNCHANGED`：新证据不足以改变原判断；
- `REVISED`：明确指出新增证据、旧判断哪里改变、为什么改变；
- `WITHDRAWN`：反证或资料修正足以撤销原判断。

禁止：
- 事情发生后悄悄把旧预测改成另一种解释；
- 只换措辞却不承认结论方向已经变化；
- 把资料修正、规则升级、岁运新触发混写成同一种“解释更新”；
- 删除原始预测后再声称“之前已经预测到”。

若输入资料、排盘 profile 或计算真值发生修正，必须先标 `CALCULATION_CORRECTION`，再重新执行；不得伪装成普通解释更新。

## 5. Regression Test｜规则升级回归

任何新规则、口诀、权重、解释语法或治理补丁进入 active path 前，都要回答：

1. 它会改变哪些已有 benchmark／已锁定案例？
2. 改变是预期差异，还是未知 regression？
3. 是否破坏更高优先规则、UNKNOWN 路径或旁证隔离？
4. 是否让原本同输入的结果无理由漂移？

无法解释的结果漂移视为 regression，不得因为“新版更聪明”而直接接受。

## 6. Dual-Axis Evidence｜双轴证据

高强度现实结论必须同时区分两条轴，不得混成一个总分：

### S 轴｜Structural Evidence 结构证据

来自当前盘面内部：月令、调候、根气透藏、有路、格局体用、病药、流通、承载、十神战局、刑冲合害墓库、原局→大运→流年触发。

### V 轴｜Validation Evidence 验证证据

来自可核对的现实验证：
- A：前瞻锁定后命中；
- B：独立盲回溯；
- C：已知事件后的解释性回溯。

结构成立不等于已经获得现实验证；现实事件吻合也不得反向证明一个结构一定正确。两轴分别记录。

没有 A／B 级验证时，可以保留结构判断，但不得把“结构完成度高”偷换成“预测已被验证”。

## 7. Tie Procedure｜平手程序

当两个候选解释在当前层级无法稳定分胜负：

1. 先比较谁更符合月令、根气、透干、有路与更高优先结构；
2. 再比较 GF-13 反证数量与严重程度；
3. 再比较 A／B 级验证，不用 C 级解释性回溯强行决胜；
4. 若仍平手，保留并列候选并标 `UNRESOLVED TIE`；
5. 指出最能区分两者的下一条资料或未来验证点。

禁止为了输出一个漂亮结论而强行选边。

## 8. Governance Stop Rule｜治理停止规则

出现以下任一情况，应停止继续提高结论精度：

- 出生资料／时辰／地点可靠性不足，且该模块依赖这些资料；
- 上游 Gate 未完成；
- 关键计算真值存在未解决冲突；
- 主结构与强反证相互抵消，且 Tie Procedure 无法决胜；
- 用户要求的时间精度高于现有证据能支持的粒度；
- 只能靠低权重旁证或 C 级事后解释才能维持结论；
- 继续扩写只会增加叙事，不会增加可区分证据。

停止后必须输出当前可支持的最高层级：`不作判定`、`并列候选`、`较高概率` 或更粗时间窗，而不是编造确定答案。

## 12. P2 运行锁｜2026-09-15

当前强制结构动力学规则：

- 穿／害＝结构性损耗／功能受损，不等于控制或制取；
- 十神本体不变，刑冲制化只能改变功能状态与现实象；
- 六冲＝高强度结构触发器，不预设吉凶；
- 墓库采用动态状态判定，禁用「逢冲必开、逢合必闭」；
- ODL 有路与 FC 有效流通分开判；
- 神煞维持低权重三级旁证；
- 万物类象采用非排他多重映射；
- 跨术数同源只作哲学／语义旁证，不互改 calculation truth。

完整定义、反例与禁用项见：`docs/STONE-R6.2.1-P2-STRUCTURAL-DYNAMICS.md`。

## 13. P3 运行锁｜2026-09-18

当前强制偏枯／病藥规则：

- 偏枯不得按五行字数、百分比、缺字或不透直接判；
- 「偏」分为偏而能用／偏而成病；「枯」分为枯而有源／枯而无源；
- 特殊格先过独立真假 Gate，极旺／极弱不得自动升格；
- 病是功能故障，药是功能修复，不等于固定某一五行；
- 偏枯 Gate 后必须接 ODL，再接 FC；有路不等于有效流通；
- 墓库藏干不得视为可直接取用，逢冲不得自动视为药神出库；
- 五行象义不得直接推出人格、疾病、职业、婚姻或财富；
- 风水、颜色、家具、材质、方位、宠物、植物只可作传统文化／生活象义，不能进入核心补命算法；
- 通根与十二长生分开判定，不建立固定倍数或固定位置权重。
- 氣勢集中只可作「主軸可能更明顯」的候選訊號，不得直接等同人格、方向或成就；
- 雙強相戰只先標結構張力，必須續查旺衰、根氣、通關、制化、受損對象與 FC；
- 中和不等於五行平均；缺項不等於病、補項不等於藥；
- 通關只在兩神真實相戰且第三者可承接生化時成立，不作所有失衡的通用詞；
- 跑步／游泳／重量訓練等生活五行映射只作現代象意，不得反向修改格局、喜用、病藥或歲運；
- 所有八字／命理分組继承同一 CURRENT 主链；專項只放大本步，不得跳過上游 Gate。

完整定义、六态输出、反例与禁用项见：`docs/STONE-R6.2.1-P3-PINKU-BINGYAO-GATE.md`。
