# 昭梧｜Complex Question Reasoning Layer
Status: ACTIVE SPEC
Date: 2026-10-07
Runtime target: complex / long-tail / multi-person / multi-condition questions only

## 1. 目的

昭梧的簡單問題仍由 deterministic R6.2.1 + P2 + P3 runtime 直接回答，再由 answer-writer 做白話改寫。

只有當問題出現「多人、多題、多條件、比較、排名、時間、情境、第三方、高風險邊界」等複雜性時，才啟動 answer-reasoner。

answer-reasoner **不是第二套排盤引擎**。它不能重新算命、不能新增十神／格局／用神／歲運事實；它只能拿現有 runtime 已產生、帶 fact ID 的結果做：
- 組合；
- 優先級排序；
- 條件化；
- A/B 比較；
- 主問題／次問題覆蓋；
- 限制與現實變數整理。

## 2. 三層答案架構

1. **Truth layer**：R6.2.1 + P2 + P3 deterministic runtime。唯一可生成命盤事實的層。
2. **Reasoning layer**：answer-reasoner。只消化 fact packet，不能新增命理事實。
3. **Expression layer**：簡單題 answer-writer；複雜題由 reasoner 直接給精簡答案。前台驗證失敗時全部 fail closed 回 rule answer。

優先順序：

complex reasoner → wording writer fallback → deterministic rule answer

任何 AI 層失敗都不得讓結果頁白屏，也不得覆蓋 deterministic truth。

## 6. 複雜題答案 Contract

複雜題的最終答案必須：
1. 第一個結論直接回答主問題。
2. 明確覆蓋最多 6 個次問題，不得用一段泛話假裝全答。
3. 每個實質結論由 fact ID 支持。
4. 有衝突時排序：CURRENT 子平主判 > 已接入歲運 > 現實限制 > 旁證。
5. 只能有一個客戶可見主結論；不同方法衝突時降信度，不並列兩套互斥答案。
6. 多人題只回答本人可判範圍；無對方命盤不讀心。
7. A/B 題要明確選或明確說為何不能強選。
8. 時間題要給窗口或明確降級。
9. 高風險題一定保留專業邊界。
10. 最後只給一個最優先現實行動。

## 7. 典型長尾題覆蓋樣本

### 感情
- 「我跟他現在曖昧半年，他最近變冷，我要不要繼續等？如果等，看到什麼時候？」
  - 答：本人是否值得繼續投入 + 可觀察條件 + 時間窗口；不讀對方心。
- 「前任回來找我，我現在也有新對象，哪一個更適合？」
  - 答：若沒有兩人資料，不做雙方合盤；先比較本人承載、現實條件、退出成本。
- 「他是不是出軌？」
  - 答：不能由本人命盤判定事實；只能列應核對的現實行為與本人關係節奏。
- 「這段婚姻還值得救嗎？孩子、錢、住處都綁在一起。」
  - 答：婚姻主問題 + 家庭／財務次問題 + 安全與法律邊界。

### 工作
- 「老闆說要升我，但薪水不變，我又有另一個 offer，留還是走？」
  - 答：職涯比較 + 薪酬／責任／退出成本 + 時間。
- 「我適合自己開店還是繼續做高級髮型師？」
  - 答：工作模式比較，不只輸出『適合某五行行業』。
- 「我和合夥人最近一直吵，要拆夥嗎？今年什麼時候談最好？」
  - 答：合作風險 + 退出條件 + 時間；不替合夥人讀心。
- 「客戶最近一直流失，是我運不好還是定位錯？」
  - 答：命理只能補本人節奏，商業數據／定價／服務需列為最大現實變數。

### 家庭
- 「我爸最近身體差，我是不是今年要特別擔心？」
  - 答：不得用本人盤診斷父親；只談本人照護壓力與應做的現實醫療安排。
- 「媽媽和伴侶一直不合，我應該站哪邊？」
  - 答：本人邊界、責任與衝突處理；不把六親標籤當真人善惡。
- 「孩子明年要換學校，我們要不要一起搬家？」
  - 答：家庭／教育／居住／時間的多域整合。

### 財務／商業
- 「現在借錢擴店值不值得？如果不擴，會不會錯過最好時機？」
  - 答：擴張決策 + 現金流風險 + 時間；不保證收益。
- 「投資人要拿 30% 股權，我該不該接受？」
  - 答：本人商業承載 + 控制權／條款／退出成本；命理不替代估值和法律意見。
- 「今年適不適合買房，同時我還想換工作？」
  - 答：兩個重大決策的現金流與時間衝突，不各自孤立作答。

### 遷移／旅行
- 「悉尼、墨爾本、福州三個地方哪個更適合我長住？」
  - 答：若只有本人盤可做本人適配排序；現實成本／工作／簽證是必要條件。
- 「明年回國五週，哪個月走比較順？」
  - 答：已接入月份窗口 + 旅行負荷，不新增月份。
- 「如果先移民再創業，和先創業再移民，哪個順序好？」
  - 答：sequence + conditional + career + migration。

### 自我
- 「我到底適合做管理還是技術？為什麼我每次做到管理就很煩？」
  - 答：能力 + 工作功能 + 已有結構事實 + 現實驗證。
- 「我的天賦很多，但哪個最值得拿來賺錢？」
  - 答：天賦與商業變現分開；不能把天賦詞直接等同賺錢能力。
- 「為什麼我每幾年都會突然想全部推倒重來？」
  - 答：可用結構／歲運解釋反覆模式，但不得事後硬湊。

### 高風險
- 「哪個月做手術最好？」
  - 答：命理不得代替醫生排程；最多談生活負荷，臨床條件優先。
- 「官司今年會不會贏？」
  - 答：不保證勝敗；期限、證據、律師策略優先。
- 「哪一隻股票最旺我？」
  - 答：拒絕用命理指定標的；可談風險承受與現金流。
- 「我能活到幾歲？」
  - 答：不作壽命預測。
- 「我未來孩子會是什麼性格？」
  - 答：未出生個體沒有自己的出生盤，不補造人格。

## 8. 模型與成本策略

- 簡單題：不啟動 reasoner。
- 複雜題：answer-reasoner 使用可配置模型，初始為 `gpt-6-luna`。
- 原因：複雜題需要語義分解與多條件整合，但不需要讓高價模型重新計算 deterministic 命理。
- 每次最多 40 個 fact、最多 6 個次問題。
- 每訪客每日設 cap；全站月 cap；任何 provider 錯誤 fail closed。
- 模型成本不得成為新增訂閱或新基礎設施的理由。

## 9. 驗收

一個複雜答案只有在下列全部成立時才可替換 rule answer：
- reasoner source 正確；
- answer / next 有效；
- sentence cap 通過；
- 沒有必然化／恐嚇／內部 prompt；
- 所有 evidenceIds 都存在於 fact packet；
- coverage 足以覆蓋主問題與主要次問題；
- 第三方／高風險邊界沒有被突破。

否則直接回退現有答案，不向客戶暴露錯誤。
