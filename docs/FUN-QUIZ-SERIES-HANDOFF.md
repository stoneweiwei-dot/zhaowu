# 昭梧趣味測驗系列｜生成與實作交接指令

狀態：ACTIVE HANDOFF
用途：交給其他 AI／工程代理（包含 OK）接續實作時，直接以本文件為規格，不重新猜產品方向。

## 1. 產品定位

在昭梧首頁建立獨立的「趣味測驗系列」session／入口。目的不是把首頁變成傳統算命表單，而是讓使用者先玩、先產生好奇，再自然導向八字守護獸、完整命盤或其他深度功能。

硬性邊界：
- 不改壞現有核心命理分析主流程。
- 趣味測驗本身不要求使用者先輸入出生資料。
- 不把心理／趣味測驗結果冒充正式八字結論。
- 有命盤時才可以追加命局層結果；沒有命盤時不得偽造命局瑞獸。
- 完整命理報告仍維持現行收口：總體概括＋身體需要注意，不因趣味測驗新增第三、第四個報告 session。
- 手機優先，尤其 iPhone Safari；首頁不能被 loading gate 阻塞。
- 三語支援：繁體中文、簡體中文、英文。英文使用自然、簡明、澳洲語境可理解的 plain English，避免命理術語堆砌。

## 2. 系列架構

首頁顯示一個獨立「昭梧趣味測驗系列」區塊。它是一個可持續增加測驗的系列容器，不要每新增一個測驗就重新設計首頁。

第一個正式測驗：

### 你的內在動物 × 命局瑞獸

分成兩層：

A. 趣味人格層
- 使用者直接作答，不需要生日。
- 目前規格為 12 題。
- 結果池：蒼鷹、狼、靈狐、玄鹿、玄豹、玄鶴、靈鯨、天馬。
- 每個答案對結果原型累積權重，最後依分數與 deterministic tie-break 得出唯一主要結果。
- 結果要解釋：核心本能、在人群中的反應、壓力下的模式、優勢、容易卡住的地方、當下提示。
- 不寫成醫療診斷、人格障礙診斷或宿命判決。

B. 命局層（可選）
- 僅當系統已有可靠八字 Chart 時啟用。
- 使用既有命理引擎的命局瑞獸／Guardian Beast 推導，不重新發明另一套八字算法。
- 命局瑞獸至少應依現有 chart 的日主、月令、喜用／工作元素等真實結構推導；不得只按生肖換神獸。
- 沒有出生資料／Chart 時，顯示「想看看你的命局瑞獸？」之類的自然下一步，引導到既有出生資料流程，但不能阻止使用者先看趣味結果。

## 3. 雙結果關係

當趣味人格層與命局層都存在時，再計算兩者的關係，不把兩個結果硬合成一隻新動物。

關係類型：
- 內外同象：兩層傾向高度一致。
- 內外相生：兩層不同，但互相補足／推動。
- 內外相制：一層會約束或修正另一層。
- 內外異象：內在偏好與命局運作方式明顯不同。

輸出時說清楚「你喜歡／本能怎麼反應」與「命局實際怎麼運作」的差別。不得把趣味答案倒過來修改八字計算結果。

## 4. 題目生成規格

生成或修改 12 題時遵守：
- 題目必須是生活情境，不直接問「你覺得自己像狼還是狐狸」。
- 每題選項語義要有區分，但不要讓使用者一眼看出哪個選項對應哪隻動物。
- 避免十二題反覆問同一件事。
- 題目至少覆蓋：陌生環境、群體位置、衝突反應、決策方式、壓力處理、自由與規則、親密距離、觀察／行動節奏、風險偏好、獨處方式、保護欲／邊界、直覺與理性。
- 不用 MBTI 題庫換皮，不抄現成心理量表。
- 結果必須 deterministic：相同答案得到相同結果。
- 所有題目必須作答後才可提交，除非產品日後明確改規格。

## 5. 結果文案規格

趣味結果先給一句非常直接的答案，例如「你的內在動物：靈狐」。接著才是 3–6 個短段落的解釋。

禁止：
- 空泛星座式萬用文案。
- 恐嚇、詛咒、神秘權威口吻。
- 宣稱測驗能證明前世、疾病、精神狀態或客觀命運。
- 為了導流故意把免費結果寫殘缺。

命局瑞獸層必須標示它是命局結構的象徵化呈現，不是超自然事實聲明。

## 6. 首頁 UX

趣味測驗區應像「可以點進去玩的入口」，不是一大段說明書。

首頁卡片最低資訊：
- 系列名：昭梧趣味測驗
- 測驗名：你的內在動物 × 命局瑞獸
- 一句鉤子
- 約需時間／題數（可顯示 12 題）
- 開始測驗 CTA

不要在首頁卡片直接塞八字專業術語。完成趣味結果後才自然提供「再看命局瑞獸／完整分析」入口。

## 7. 視覺規格

沿用昭梧現行網站視覺系統，不另起一套廉價測驗網站 UI。中國本土題材使用中國傳統畫風語言；整體以舊宣紙／宋系圖譜／古畫冊的低飽和紙本質感為基礎，避免現代遊戲角色卡、商業仙俠海報、高飽和塑膠色與強數位光效。

動物結果圖若日後生成：
- 預設 9:16 iPhone 適配。
- 主體清楚，背景保留呼吸感。
- 可做古代異獸圖譜／宋系博物圖志式呈現。
- 不要把八隻動物畫成同一個模板只換頭。
- 圖片文字與資料分離，先保證結果文字可交付；圖片失敗不得阻塞測驗結果。
- 對外生成成品按站主既定版權規則處理 STONE 原創水印；不要讓生成模型把水印直接畫成亂碼，應在乾淨圖完成後再疊加。

## 8. 與現有命理報告的整合

如果使用者之後進入完整命理報告：
- 可以把命局瑞獸作為「總體概括」內的一個象徵性結果／短段落。
- 不建立新的固定報告 session。
- 趣味測驗的內在動物可以作為互動紀錄，但不得成為八字計算輸入，不得改變旺衰、格局、喜用、大運流年等正式結果。
- 正式命理計算 Truth Layer 優先級永遠高於趣味測驗。

## 9. 工程要求

實作前先讀現有相關程式，不要另造重複模組。優先尋找並復用：
- 首頁趣味測驗區／gateway。
- quiz scoring／result mapping。
- `src/lib/report/guardian-beast.ts` 或現行 Guardian Beast 推導。
- 現有出生資料與 Chart state。
- 現有三語 locale 系統。
- 現有統一報告 renderer。

新增功能必須有 regression tests，至少驗證：
1. 12 題未答完不能提交。
2. 同一答案組合結果 deterministic。
3. 無 Chart 時不生成命局瑞獸。
4. 有 Chart 時使用現有 Guardian Beast 邏輯。
5. 趣味答案不能修改 Chart 或正式命理結論。
6. 雙結果關係四分類可穩定計算。
7. 三語不串語。
8. iPhone 首屏與測驗流程不被 loading／modal 阻塞。
9. 完整報告仍只有「總體概括＋身體需要注意」的現行結構，不因本功能重新膨脹。

## 10. 給接手 AI／OK 的直接執行指令

你正在維護 `stoneweiwei-dot/zhaowu`。請先閱讀本文件、`AGENTS.md`、`docs/CURRENT-STATE.md`，再檢查目前 main 上已存在的趣味測驗相關程式與測試。不要從零重寫，也不要建立第二套命理引擎。

任務：把「昭梧趣味測驗系列」做成可持續擴充的首頁互動產品。第一個測驗固定為「你的內在動物 × 命局瑞獸」。保留純趣味人格層與正式命局層的資料邊界；無出生資料也必須能完整玩完；有 Chart 才追加命局瑞獸與內外關係。所有正式八字判斷只能讀取既有 Truth Layer／Chart，不得由測驗答案推導或修改。

修改前先盤點現有檔案、routes、components、tests 與資料流；能復用就復用。完成後跑 deterministic tests、TypeScript check、production build 與既有 Mobile Safari regression。任何既有測試失敗都要找根因，不得刪測試、跳過測試或用假資料讓 CI 變綠。只有在 main 對應 CI 全綠且 production deploy 確認後，才能聲稱「完成部署」。

## 11. 後續系列擴充原則

之後新增趣味測驗時，全部掛在同一系列容器下。每個測驗應有自己的 `id / version / questions / scoring / result archetypes / locale copy`，但共用測驗 shell、進度、結果頁、分享與導流結構。

新的測驗可以輕鬆、有文化感、有世界觀，但不要為了數量製造一堆換皮題庫。每個新測驗都要先回答：它測的是什麼、與昭梧哪個深度功能有自然連接、哪些內容只是趣味象徵、哪些內容屬正式命理。這四件事不清楚就不要上線。
