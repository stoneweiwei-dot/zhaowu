# 昭梧｜问题导向完整报告（ZW-FOCUSED-REPORT-1.0）

> 本文件取代旧的固定九页客户报告结构。固定九页不得再作为新报告产品要求、测试要求或 UI 要求复活。

## 1. 产品原则

完整报告不按页数凑内容，只围绕用户当前这一问展开。

默认固定四个核心区：

1. **直接结论** — 第一屏直接回答，不先讲方法。
2. **命理依据** — 只列与这一问直接相关、当前引擎已经成立的依据。
3. **时间与节奏** — 说明当前节奏；时间／出行题必须给可执行窗口。
4. **现实行动** — 把结论翻成现实中可以执行的下一步。

条件区只有相关时才出现：

- **关系与对象**：仅感情／关系问题出现。
- 以后新增条件区必须先证明与问题直接相关，不得为了报告长度默认出现。

## 2. 禁止项

- 禁止固定九段／九页。
- 禁止为了凑数量塞入用户没问的工作、感情、财务、健康、家宅等旁支。
- 禁止自问自答、内部推理、实现说明、模型说明、UUID、时间戳、验收文案。
- 禁止把尚未实现的格局、正式病药、完整刑冲合害或其他未接入流派写成已完成事实。
- 禁止重复第一节直接答案来凑字数。

## 3. 单一答案来源

报告只能消费 `finalizeReading` 之后的最终 Reading。

前台直答、完整报告、保存版和后台读取必须来自同一份最终结果；已保存报告打开时不得 live 重算成另一套答案。

## 4. 图像与文字解耦

个人命诰图／视觉成像是独立增值模块：

- 用户主动触发生成；
- 真实生成走 Supabase Edge Function + Storage；
- 图像失败不得阻塞文字报告；
- 禁止 Canvas / SVG / CSS 模板冒充真实 AI 图。

## 5. 天龙八部 × 佛教吉祥意象视觉系统

用户提供的 STONE 原创参考图作为**视觉语言来源**，不是要求全站堆满图片。

当前使用原则：

- 报告顶部使用一张压暗后的天龙／法器主视觉作为品牌锚点；
- 报告功能意象统一为六枚：**法轮、莲、盘长结、法螺、双鱼、宝瓶**；
- 视觉色系：乌金黑／深茶褐／古金／青玉绿／象牙白；
- 不再把随机幽灵 SVG / 全页散落小图标作为主视觉系统；
- iPhone 390–430 px 优先，图不能遮文字、按钮或影响阅读。

## 6. 兼容旧记录

Supabase 历史记录里可能仍保存 `mother_draft.ninePages`。这是历史字段名，不代表当前产品仍是九页。

兼容层可以继续读取旧字段，但新 UI、新测试、新文档不得把“九页”作为客户产品要求。
